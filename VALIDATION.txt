VALIDATION - COMMUNITY 1.0.1

Passed 145 automated tests on Windows with Python 3.13 and PyMuPDF 1.26.3.
This includes nine new section-record tests: allocation across pages, retained
first-seen order, merged geometry/subtracts, filtered shares, Count units,
decimal separators, zero/negative values, malformed inputs and inconsistent
item metadata. A two-page raw-record export matches an equivalent grouped export
in rendered pixels, searchable text, layer properties and annotation references.

Existing tests cover source matching/labels, legends, layer visibility and
highlight actions, multiplier placement, picker controls, preview order/removal/
history/view preferences, community installation paths and source exclusions.
A static bridge check confirms removal of named inherited routines/variables,
presence of the raw-section protocol and use of parent Qty and Qty.inputUnits.
Static checks do not compile Pascal or certify the embedded engine.

The installer was run against a fresh isolated folder. It created its own virtual
environment and installed pinned PyMuPDF 1.26.3. Using only this installed runtime,
all seven runtime modules imported, Tk initialized, and a raw-section manifest
rendered successfully with a searchable 500 LN FT quantity and native layer
visibility/highlight actions. No changes were made to the normal installation.

The synthetic demo generator now uses SectionRecordsV1. Both regenerated pages
have exactly the same rendered pixels, text and layer properties as the previously
visually checked 1.0.0 demo. No real job drawing was used.

All Python sources parsed successfully. Personal working-file hashes were checked
against the pre-review baseline. The archive excludes original plugin references,
the separately delivered bridge TXT, temporary runtimes, settings, logs, cached
bytecode and client drawings. See SOURCE_REVIEW.txt for provenance-review scope.
